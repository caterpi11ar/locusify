## 新账号起步目标

当前账号按“新账号起步”运营，不因粉丝少、历史转化数据缺失或单日指标无增长而停止内容实验。起步期的首要任务是用小步、真实、可复核的内容实验建立：

1. 稳定且不过量的发布节奏；
2. 不超过 3 个核心受众场景；
3. 清晰的“旅行照片 → 路线故事”产品价值表达；
4. 第一批真实评论、收藏、分享及产品访问/激活信号。

## 起步期行动规则

- 内容实验优先级高于等待完整历史数据；缺少产品访问、激活、留存或转化数据只降低结论置信度，不单独阻止发布。
- 每个成功 Run 应优先形成一个最终可执行的内容实验；当天不适合发布时，再选择真实评论回复或单条非批量相关互动。
- 发布目标仍为滚动 7 天 2—3 条，硬上限 3 条；相邻实际发布时间至少 48 小时，同日最多 1 条。
- 新账号起步不是绕过发布门禁。优先从平台发布时间、已知定时任务和本仓库执行记录核验窗口。
- 若平台无法提供历史发布时间，启用保守冷启动：以 `effectiveFrom` 或最近一次已知发布/定时发布时间中的较晚者作为安全锚点；满 48 小时且本仓库无同日发布、无已知待发布冲突时，才可将 `publishWindow` 判为 `eligible`。不能确认账号在 `effectiveFrom` 后是否由仓库外发布过内容时，仍标记 `unknown`。
- 没有合规媒体、最终文案或完整发布参数时不得发布；Coordinator 应把“补齐最终内容包”作为本 Run 的执行准备，而不是把产品侧指标缺失误写成发布硬阻塞。
- Brand blocking objection 必须针对具体动作和具体风险；不得仅因“新账号、粉丝少、数据少”笼统阻断全部平台动作。

## 起步期内容实验方向

按现有可见信号优先测试，结论均保持待验证：

1. 家庭旅行记忆：不会做 vlog，也能保存父母的旅行路线故事；
2. 旅行地图与路线回顾：把散落照片整理成可回看的足迹；
3. 相册整理痛点：照片很多，但难以快速找回一次旅行的完整故事。

每次发布只测试一个主要变量，并记录受众、问题、价值主张、内容形式、成功信号和停止条件。不得把历史点赞排序直接当成主题已验证。

## 退出与复盘

到 `reviewAt` 由 Team 复盘并决定：

- 延长 `new_account_bootstrap`；
- 切换到 `validation`；
- 因认证、合规或持续数据故障暂停。

复盘至少检查发布执行数、有效评论/深度互动、主题差异、产品侧最小价值信号和风险事件。阶段切换必须更新本文件，不由每日 Agent 静默改变。
