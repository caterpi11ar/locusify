真实 dev server · 真实上传 4 张 GPS 照片 · 真实轨迹回放 · 抓取 16:9 cropRef · Chrome 155 · 1920×1080@30fps

上一版的效果图是手搓复刻场景，作废。 这一版跑的是仓库里的真实 app：真实 dev server、真实上传抽屉、真实 EXIF 解析、真实 4 个 marker、真实 replayStore 回放。下文所有 PSNR/SSIM 都是「离线合成像素」对「你的 app 此刻真实渲染的像素」。

TL;DR

  • 离线合成能做到 PSNR 32.2–32.6 dB / SSIM 0.994–0.996，平均通道差 0.27–0.33，差值 >40 的像素只有 0.14–0.16%。
  • 整帧光栅每帧 195–292 ms（3–5 fps），直接淘汰。
  • 分层合成（地图 drawImage + 画布内 blur 造玻璃 + 静态层缓存 + 文字补丁）每帧 0.7–16.8 ms，静态层 118–157 ms 只做一次。
  • WebCodecs H.264：90 帧 1080p30 用 2.44 s（1.23× 实时），6.2 MB；编码回环 45.08 dB / SSIM 0.9956。
  • ffmpeg.wasm 核 31 MB、GPL-2.0-or-later、0.29× 实时 → 只作兜底，不进主链路。

5. 剩下的差异在哪

把差值按 32×32 分块聚类，全画面只有 1 个区域平均差 >12：(192,512)–(320,640)，128×128，平均 19.6、最大 218。放大看就是一小段文字的字形相位/抗锯齿差异——同一字体同一字号，但 SVG foreignObject 内的文字光栅化相位与页面不同。地图瓦片、玻璃卡、照片缩略图、路线、底栏、二维码都在 0.1% 以内。

ffmpeg.wasm 的代价：@ffmpeg/core@0.12.10 单线程核 31 MB（ffmpeg-core.js + ffmpeg-core.wasm），好处是不需要 COOP/COEP、不需要 SharedArrayBuffer；许可证 GPL-2.0-or-later，Web 分发要满足 GPL 的独立可替换与源码声明义务。它唯一优势是产物小、老浏览器兼容。

8. 建议

  1. 生产路线走分层合成 + WebCodecs；每帧整棵树栅格化（200 ms+）是死路。
  2. 静态层在编码前排干（3 个 waypoint → 4 个静态状态，每个约 130 ms），避免录制中途卡顿。
  3. 玻璃必须手工补：SVG foreignObject 里 backdrop-filter 没有背面可采样，要把地图先画进画布、再对该区域 ctx.filter = 'blur(Npx)' 自绘。
  4. 文字补丁只重画变了的叶子节点（textContent 变化的最小元素），11–17 ms/帧，仍在 33 ms 预算内。
  5. ffmpeg.wasm 只作按需兜底（Safari / 旧内核 / 需要极小体积），不进主链路。
  6. 屏幕捕获保留为「用户就要 100% 原样且愿意授权」的兜底。
